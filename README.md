## 一、功能简介

MJ CANScope 把「**收报文 → 配信号 → 看曲线 → 判报警**」这条链路做成了闭环，主要解决工程师在总线上做**信号级**分析时反复切换工具的问题。

| 能力             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **全系设备支持** | 内置 **82 种** 周立功设备类型（USBCAN / USBCAN-II / USBCAN-E-U / USBCANFD / ZPSCANFD / CANalyst-II+ / ZCAN 系列），含 CANFD 与网络设备 |
| **信号级解析**   | 字节级（占 1/2/4 字节）+ **位级**（4bit/8bit 拆分）双层模型，支持大小端、有符号、量纲换算 |
| **实时曲线**     | 任意报文任意字节/位信号实时成图，单图叠加 / 分图平铺双模式，悬停读数、拖动平移、滚轮缩放 |
| **条件报警**     | 按字节挂报警条件（等于 / 大于 / 小于 / 区间），命中即变色并计数 |
| **配置闭环**     | Simulink `.slx` 模型直接解析成接收/发送配置，配置可导入导出  |
| **收发配置互转** | 接收配置 ⇄ 发送配置 双向转换，一个配置文件当另一个用         |
| **离线分析**     | 支持导入 ASC / CSV / TXT 报文文件，无需设备即可回放分析      |
| **录制回放**     | 实时录制总线数据存成 ASC/TXT，可再导入回来离线分析           |

## 二、界面与功能详解

主界面分为 **6 个页签**。

### 1. 报文监控

实时接收并显示 CAN / CANFD 报文。

- **连接区**：设备类型、索引、通道、波特率；网络设备（CANET-TCP/UDP、CANWIFI、CANalyst-II+）另有 IP / 端口配置弹窗
- **报文表**：序号、时间戳、CAN ID、ID 名称/注释、Byte0~Byte7、计数、状态
- **显示选项**：ID 显示基数下拉（十六进制 / 十进制）、数据显示基数下拉（十六进制 / 十进制）、`显示注释` 开关
- **ID 筛选**：按报文 ID 下拉过滤，只看关心的帧
- **状态栏**：累计报文数、当前连接状态

### 2. 报文接收配置

为每个报文 ID 建立语义化定义。

- **报文级**：ID、名称、注释、标准帧/扩展帧、正常色 / 报警色
- **字节级**：每个字节的名称、注释、**占字节数**（1/2/4，多字节信号按小端合并）
- **报警条件**：每个字节可挂多条条件，满足即按报警色显示![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/7dc9ef04f5bd4b35870defb45ffb01f1.png

### 3. 曲线显示

本工具的核心页面。

- **导入口**：`从配置导入`（取接收配置里已定义的信号）/ `从已接收导入`（取实际收到的报文）

- **双模式**：

  - **单图叠加** —— 所有曲线共用一套坐标轴，适合横向对比
  - **分图平铺** —— 每条曲线一个独立子图，各自的 X/Y 轴

- **分组图例**：按报文 ID 分组，同一 ID 排一行，行首只写一次 ID，后面接颜色方块 + 字节序号 + 注释 + 物理量范围

  ```
  0x100:  ■ B0(转速) [0~250]   ■ B1(油温) [-40~215]   ■ B2 [0~255]
  0x2A0:  ■ B0 [0~65535]
  ```

- **交互**：鼠标悬停读数（十字光标）、拖动平移、滚轮缩放、`暂停` / `复位X` / `全览X`

- **显示开关**：点图例上的颜色方块可单独隐藏 / 显示某条曲线

- **字节快捷选择**：B0~B7 一键全选 / 全清

### 4. 报文发送

手动或周期发送报文。

- 支持标准帧 / 扩展帧、单次 / 周期发送
- 发送内容可由**已配置的信号**拼装，多字节信号自动按大小端拆分
- 数据支持 HEX 输入（8 字节，空格分隔）
- 实时显示发送历史与结果
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/4460863b30024a92be62324a6e694d36.png)

### 5. 报文发送配置

定义要发什么、怎么发。

- 信号表：名字、字节位置、占字节数、值、量纲换算
- 周期、帧 ID、帧类型等发送参数
- 配置可导入导出，供现场复用
- **与接收配置互转**：接收配置描述「这帧我收到了，怎么解读」，发送配置描述「我要发这帧，怎么拆」——两者描述的是同一个 CAN 帧，工具内置双向转换，一个配置文件可以直接当另一个用（转换是**有损**的，会在返回说明里讲清哪些特有字段丢了，如报警条件、默认按钮值）

### 6. 报文配置解析

直接读 Simulink 模型，**不用手抄信号表**。

- 解析 `.slx` 内的总线配置，自动抽出报文 ID、信号名、起始位、位长、量纲、字节序
- 解析结果预览，**一键导入**到「报文接收配置」和「报文发送配置」
- 解析器与 Python 版输出做逐字段比对，保证两条产线结果一致

## 三、快速开始

### 环境要求

- Windows 64 位
- 周立功 CAN 盒 + 对应驱动（仅连接硬件设备时需要）
- 免安装版**不需要**额外装 Qt 或编译环境

### 使用步骤

1. **连接设备**
   - 在顶部选择设备类型、索引、通道、波特率
   - 网络设备另填 IP / 端口
   - 点「连接」，状态栏显示「已连接」
2. **开始接收**
   - 点「开始接收」，报文实时出现在表格里
   - 「报文监控」页可切换 ID/数据的进制、开关 `显示注释`、按 ID 筛选
3. **配置信号**（可选）
   - 「报文接收配置」页添加报文，填 ID / 名称 / 字节注释
   - 需要位级信号时，在字节表的「占字节数」列选 4bit 或 8bit，就地展开
4. **看曲线**
   - 「曲线显示」页 → `从配置导入` 或 `从已接收导入`
   - 选报文 ID → 点字节 B0~B7 → 曲线实时刷新
   - 点图例方块可隐藏不需要的曲线
5. **设置报警**
   - 在接收配置里给字节加条件，命中后表格里该字节变报警色
6. **导出结果**
   - 菜单 `文件 → 导出报文`（TXT / CSV）或 `导出配置`（JSON）

### 录制与离线分析

- `Ctrl+R` 或菜单 `文件 → 开始/停止录制`：把总线实时数据录成 `.asc`（Vector 格式，可直接用 CANoe 打开）或 `.txt`
- `文件 → 导入报文`：把 `.asc` / `.csv` / `.txt` 报文文件读进来，无需连接设备即可浏览、配置信号、画曲线
- **注意**：程序正常退出时才会补写 ASC 的 `End TriggerBlock`。请正常关闭程序再取文件，不要直接杀进程，否则文件尾部不完整，CANoe 可能判为截断

### 快捷键

| 快捷键   | 功能            |
| -------- | --------------- |
| `Ctrl+R` | 开始 / 停止录制 |
| `Ctrl+E` | 导出配置        |
| `Ctrl+I` | 导入配置        |

## 四、常见问题

**Q：双击 exe 提示「找不到 Qt6Core.dll」**
A：没解压，或没跑 `deploy.ps1`。本程序是免安装包，必须**完整解压到本地目录**再运行，不能直接在压缩包里点 exe。

**Q：提示「no Qt platform plugin could be initialized」**
A：缺 `platforms/qwindows.dll`。用 `deploy.ps1` 重新打包即可。

**Q：连不上设备**
A：依次检查 ① 设备驱动是否安装 ② 设备类型/索引是否选对 ③ 波特率是否与总线一致 ④ 部分设备需以管理员权限运行。

**Q：网络设备参数填了但连不上**
A：先跑 `MJ_CANScope.exe --nettest` 看参数能否被 ZCAN 内核正确接收；再确认 PC 与设备在同一网段。

**Q：曲线是乱的 / 在 0~255 之间跳**
A：这条曲线画的是**整字节**而不是具体信号。需要在「报文接收配置」里给该字节配上位定义（占字节数选 4bit / 8bit）或多字节跨度。

**Q：数值不对，比如温度显示成几百**
A：检查信号定义里的 `scale` / `offset` 和字节序（大小端），尤其是跨字节的信号。

**Q：导入 Simulink 模型后信号对不上**
A：用 `--slx-export` 导出 JSON，与 Python 版输出逐字段比对；两边应当完全一致。

**Q：录制的 ASC 文件在 CANoe 里打不开**
A：程序退出时会补写 `End TriggerBlock`，请**正常关闭程序**后再取文件，不要直接杀进程。---
