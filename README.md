## 一、功能简介

MJ CANScope 把「**收报文 → 配信号 → 看曲线 → 判报警**」这条链路做成了闭环，主要解决工程师在总线上做**信号级**分析时反复切换工具的问题。

| 能力 | 说明 |
|---|---|
| **全系设备支持** | 内置 **82 种** 周立功设备类型（USBCAN / USBCAN-II / USBCAN-E-U / USBCANFD / ZPSCANFD / CANalyst-II+ / ZCAN 系列），含 CANFD 与网络设备 |
| **信号级解析** | 字节级（占 1/2/4 字节）+ **位级**（4bit/8bit 拆分）双层模型，支持大小端、有符号、量纲换算 |
| **实时曲线** | 任意报文任意字节/位信号实时成图，单图叠加 / 分图平铺双模式，悬停读数、拖动平移、滚轮缩放 |
| **条件报警** | 按字节挂报警条件（等于 / 大于 / 小于 / 区间），命中即变色并计数 |
| **配置闭环** | Simulink `.slx` 模型直接解析成接收/发送配置，配置可导入导出 |
| **会话记忆** | 自动记住上次退出时的接收/发送配置与设备设置，下次打开直接接着用 |
| **收发配置互转** | 接收配置 ⇄ 发送配置 双向转换，一个配置文件当另一个用 |
| **离线分析** | 支持导入 ASC / CSV / TXT 报文文件，无需设备即可回放分析 |
| **录制回放** | 实时录制总线数据存成 ASC/TXT，可再导入回来离线分析 |

## 二、界面与功能详解

主界面分为 **6 个页签**。

### 1. 报文监控

实时接收并显示 CAN / CANFD 报文。

- **连接区**：设备类型、索引、通道、波特率；网络设备（CANET-TCP/UDP、CANWIFI、CANalyst-II+）另有 IP / 端口配置弹窗
- **报文表**：序号、时间戳、CAN ID、ID 名称/注释、Byte0~Byte7、计数、状态
- **显示选项**：ID 显示基数下拉（十六进制 / 十进制）、数据显示基数下拉（十六进制 / 十进制）、`显示注释` 开关
- **ID 筛选**：按报文 ID 下拉过滤，只看关心的帧
- **状态栏**：累计报文数、当前连接状态

### 2. 报文接收配置

为每个报文 ID 建立语义化定义。

- **报文级**：ID、名称、注释、标准帧/扩展帧、正常色 / 报警色
- **字节级**：每个字节的名称、注释、**占字节数**（1/2/4，多字节信号按小端合并）
- **位级**：在字节配置表里直接把某一字节拆成 4bit / 8bit，展开成 4 列或 8 列，每列填一个位信号的（名字 + 起始位 + 位长）
- **量纲**：缩放系数 `scale` + 偏移 `offset`，把原始值换算成物理量（温度可以是负数）
- **报警条件**：每个字节可挂多条条件，满足即按报警色显示

> **为什么要位级**：汽车 CAN 里一个状态字节常常塞满 8 个布尔量。以前只能把整字节当数字看，曲线在 0~255 之间乱跳，毫无物理意义。位级模型让每个开关都能单独成曲线。

### 3. 曲线显示

本工具的核心页面。

- **导入口**：`从配置导入`（取接收配置里已定义的信号）/ `从已接收导入`（取实际收到的报文）
- **双模式**：
  - **单图叠加** —— 所有曲线共用一套坐标轴，适合横向对比
  - **分图平铺** —— 每条曲线一个独立子图，各自的 X/Y 轴
- **分组图例**：按报文 ID 分组，同一 ID 排一行，行首只写一次 ID，后面接颜色方块 + 字节序号 + 注释 + 物理量范围

  ```
  0x100:  ■ B0(转速) [0~250]   ■ B1(油温) [-40~215]   ■ B2 [0~255]
  0x2A0:  ■ B0 [0~65535]
  ```

- **交互**：鼠标悬停读数（十字光标）、拖动平移、滚轮缩放、`暂停` / `复位X` / `全览X`
- **显示开关**：点图例上的颜色方块可单独隐藏 / 显示某条曲线
- **字节快捷选择**：B0~B7 一键全选 / 全清
- **Y 轴自适应**：Y 轴范围**跟着这条曲线实际观测到的值走**，不是写死的 0~255
  - 0/1 变化的开关信号 → 范围自动收到 `0 ~ 2`，高低电平一眼能分清
  - 恒为 1 的信号 → 范围是 `0 ~ 2`（整数对齐，不会出现 `0.5` 这种让人误读的刻度）
  - 0~250 的转速信号 → 范围自动放到 `-25 ~ 272`
  - 一旦你**手动框选缩放过**某条曲线的 Y 轴，自动适配就交给你，不再动它（双击可复位）
- **单点也看得见**：只有 1 个数据点的曲线（常见于导入了旧版录制的日志）会自动打点标记，不会出现「图例有颜色、图上空空如也」

### 4. 报文发送

手动或周期发送报文。

- 支持标准帧 / 扩展帧、单次 / 周期发送
- 发送内容可由**已配置的信号**拼装，多字节信号自动按大小端拆分
- 数据支持 HEX 输入（8 字节，空格分隔）
- 间隔可**直接打字输入**；填 `0` 表示不限速（尽可能快发，实际按 1ms 定时器实现，避免把界面卡死）
- **发送方式**：`正常发送` / `自收自发`
  - `正常发送`：帧真正上总线，需要总线上有对端节点 ACK 才算发出去
  - `自收自发`：**纯软件回环** —— 帧照发，同时由软件合成一份同内容的 Rx 帧回灌到接收链路，
    触发器 / 曲线 / 字节配置 / 报警条件全部能被真实验证。
    **单机台架（只插 CAN 盒、没接对端节点）也能用**，此时会明确提示「未上总线」。
- 实时显示发送历史与结果

### 5. 报文发送配置

定义要发什么、怎么发。

- 信号表：名字、字节位置、占字节数、值、量纲换算
- 周期、帧 ID、帧类型等发送参数
- **发送通道**：本页有独立的通道下拉（CH0…CHn），与「报文发送」页各用各的，互不联动
- **发送方式**：同样可选 `正常发送` / `自收发自`（与「报文发送」页任选其一即生效）
- **字节值循环发送**：每个字节可单独配置循环模式，方便批量测试


  | 模式 | 行为 | 例 |
  |---|---|---|
  | 不循环 | 固定发默认值 | — |
  | 递增 | 从起始值按**步长**递增到结束值，到顶回绕 | `0 → 10`，步长 `3` → 实际序列 `0,3,6,9,10,0…` |
  | 递减 | 从起始值按步长递减到结束值，到底回绕 | `10 → 0`，步长 `3` → `10,7,4,1,0,10…` |
  | 循环列表 | 按给定序列循环 | `0,10,50` → `0,10,50,0,10,50…` |

  > 步长不整除范围时，最后一步会**钳到边界值**再回绕 —— 上限/下限那个值一定会被发出去，不会被跳过。
  > 多字节信号按**整个信号的值**循环，每帧按字节序重新拆分（起点字节步进，从属字节跟随）。

- **值进制（重要）**：顶部「值进制」下拉决定表里数值**怎么显示、怎么输入**
  - **自动识别（默认）**：表格按十六进制显示，输入也按十六进制理解 —— 总线调试里十六进制才是主流
    | 你输入 | 实际发出的值 | 说明 |
    |---|---|---|
    | `10` | `0x10`（十进制 16） | 纯数字默认**十六进制** |
    | `0x10` | `0x10` | 带 `0x` 前缀 |
    | `0d10` / `#10` | `10`（十进制 10） | **显式写十进制** |
    | `FF` | `0xFF` | 含 A~F，只能是十六进制 |
    | `0101` | `0b0101`（5） | 带前导 0 的纯 0/1 → 二进制 |
  - 选死 `十六进制 / 十进制 / 二进制` 后，输入**严格按该进制**解释，不再猜 —— 避免发错帧

  > ⚠ 为什么纯数字默认十六进制：CAN 语境下「10」几乎总是指 `0x10`（=16）。
  > 如果按十进制理解，敲 `10` 会发出 `0x0A`，在车上可能表现为「某个开关莫名其妙动了一下」，极难排查。
  > 确实想要十进制时，写 `0d10` 即可 —— 不必去翻进制下拉。

- **HEX 列显示的是「每一个字节」**：多字节信号的每个字节格都显示**它自己那一字节**，
  不是整个信号的合并值。比如「占 2 字节、值 = 500 (0x01F4)」时：

  | | B0 | B1 |
  |---|---|---|
  | 表格 HEX 列 | `F4` | `01` |
  | 总线上实际发的字节 | `0xF4` | `0x01` |

  每一格都能和接收表 / ASC 录制文件 / 抓包工具**逐字节对上**，这是 HEX 列的意义。

  > 整个信号的合并值（`500` / `0x01F4`）放在两处，都不占表格空间：
  > - **鼠标悬停**在起点格上 → 提示框里同时给出「本字节」和「整个信号」两个值
  > - **双击编辑**时 → 编辑框里显示的就是合并值（用户改的本来就是整个信号）

  > ⚠ 从属字节（跟着起点的那个字节）不能单独改 —— 它的值由信号起点决定。改起点会按字节序自动拆到后面几个字节上。

- 配置可导入导出，供现场复用
- **与接收配置互转**：接收配置描述「这帧我收到了，怎么解读」，发送配置描述「我要发这帧，怎么拆」——两者描述的是同一个 CAN 帧，工具内置双向转换，一个配置文件可以直接当另一个用（转换是**有损**的，会在返回说明里讲清哪些特有字段丢了，如报警条件、默认按钮值）

### 6. 报文配置解析

直接读 Simulink 模型，**不用手抄信号表**。

- 解析 `.slx` 内的总线配置，自动抽出报文 ID、信号名、起始位、位长、量纲、字节序
- 解析结果预览，**一键导入**到「报文接收配置」和「报文发送配置」
- 解析器与 Python 版输出做逐字段比对，保证两条产线结果一致

## 三、快速开始

### 环境要求

- Windows 64 位
- 周立功 CAN 盒 + 对应驱动（仅连接硬件设备时需要）
- 免安装版**不需要**额外装 Qt 或编译环境

### 使用步骤

1. **连接设备**
   - 在顶部选择设备类型、索引、通道、波特率（默认 **250 kbps**）
   - 网络设备另填 IP / 端口
   - 点「连接」，状态栏显示「已连接」
   - 只做单机功能验证（曲线、配置、循环发送）时，**可以不连设备**
2. **开始接收**
   - 点「开始接收」，报文实时出现在表格里
   - 「报文监控」页可切换 ID/数据的进制、开关 `显示注释`、按 ID 筛选
3. **配置信号**（可选）
   - 「报文接收配置」页添加报文，填 ID / 名称 / 字节注释
   - 需要位级信号时，在字节表的「占字节数」列选 4bit 或 8bit，就地展开
4. **看曲线**
   - 「曲线显示」页 → `从配置导入` 或 `从已接收导入`
   - 选报文 ID → 点字节 B0~B7 → 曲线实时刷新
   - 点图例方块可隐藏不需要的曲线
5. **设置报警**
   - 在接收配置里给字节加条件，命中后表格里该字节变报警色
6. **导出结果**
   - 菜单 `文件 → 导出报文`（TXT / CSV）或 `导出配置`（JSON）

### 录制与离线分析

- `Ctrl+R` 或菜单 `文件 → 开始/停止录制`：把总线实时数据录成 `.asc`（Vector 格式，可直接用 CANoe 打开）或 `.txt`
- `文件 → 导入报文`：把 `.asc` / `.csv` / `.txt` 报文文件读进来，无需连接设备即可浏览、配置信号、画曲线
- **注意**：程序正常退出时才会补写 ASC 的 `End TriggerBlock`。请正常关闭程序再取文件，不要直接杀进程，否则文件尾部不完整，CANoe 可能判为截断

### 上次配置自动记住

程序会**记住你上次退出时的配置**，下次打开直接接着用，不用重新配一遍。

自动记住的内容：

| 类别 | 具体内容 |
|---|---|
| 报文接收配置 | 报文 ID、名称、字节注释、占字节数（1/2/4 字节）、位定义、报警条件、正常/报警颜色 |
| 报文发送配置 | 报文 ID、帧类型、字节默认值、占字节数、循环模式（递增/递减/列表）、按钮文字 |
| 设备设置 | 设备类型、设备索引、波特率、启用了哪些通道及通道号 |

行为约定：

- **存**：正常退出程序时自动写入 `session.json`
- **读**：下次启动时**静默**恢复，不弹窗、不打扰
- **不自动连接设备** —— 只记住「选了哪种设备、哪个索引、什么波特率」，连不连还是您自己点
- **不自动加载报文文件** —— 只记住配置，不自动开始回放

文件位置：

- 默认放在**程序所在目录**的 `session.json`（便携版：U 盘拷走，配置跟着走）
- 如果程序装在 `C:\Program Files` 下（普通用户无写权限），自动改存到 `%APPDATA%\MeiJie\MJ_CANScope\session.json`
- 读取时两个位置都找，便携版和安装版交替使用也能恢复

> 只想手动导出/导入一份配置给同事？用菜单 `文件 → 导出配置` / `导入配置`，那跟本功能是两回事，互不影响。

### 兼容旧版录制的日志

早期版本录制出来的 `.asc` 里，**Tx 帧的时间戳是负数**（设备计数器只有 Rx 帧才有，Tx 帧减掉起始时间就变成了 `-76.961500`）。
本工具现在能直接读这种文件：

- 解析器接受负时间戳，这些帧**不会再被静默丢掉**
- 时间轴会按前后帧**插值修正**成单调递增，曲线 X 轴分布依旧正确
- 提示栏会告诉你有多少条记录被修正过（数据内容不受影响）

如果日志是更早的版本录的、连本工具都打不开，用 CANoe 或 Vector 工具另存一份再导入即可。

### 快捷键

| 快捷键 | 功能 |
|---|---|
| `Ctrl+R` | 开始 / 停止录制 |
| `Ctrl+E` | 导出配置 |
| `Ctrl+I` | 导入配置 |

## 四、编译与开发

### 环境

| 组件 | 版本 |
|---|---|
| Qt | 6.11.1（MinGW 64-bit） |
| 编译器 | MinGW 13.1.0 (x86_64) |
| CMake | ≥ 3.16 |
| Qwt | `third_party/qwt`（已内置） |

### 方式一：Qt Creator（推荐）

1. 打开 Qt Creator → 文件 → 打开文件或项目 → 选 `CMakeLists.txt`
2. Kit 选 `Desktop Qt 6.11.1 MinGW 64-bit`
3. 构建（`Ctrl+B`）；运行前先执行 `deploy.ps1 -SkipBuild` 拉齐运行时依赖

### 方式二：命令行

```bash
# 配置
cmake -S . -B build -G Ninja \
      -DCMAKE_PREFIX_PATH=C:/Qt/6.11.1/mingw_64 \
      -DCMAKE_BUILD_TYPE=Release

# 编译
cmake --build build --parallel

# 打包（自动跑 windeployqt 收集 Qt 运行库与插件）
pwsh -File ./deploy.ps1 -Zip
```

### 一键打包

```powershell
.\deploy.ps1          # 编译 + 打包
.\deploy.ps1 -Zip     # 额外生成 zip
.\deploy.ps1 -SkipBuild   # 不编译，直接用现有产物打包
```

产物落在 `dist/MJ_CANScope_2.1_x64/`，包含主程序、Qt 运行库、Qwt 运行库、Qt 插件目录、CAN 驱动和许可证。

## 五、命令行工具

除了图形界面，程序还内置了一批**无界面自检模式**，用于现场排障和自动化回归。

| 命令 | 用途 |
|---|---|
| `--listdevices` | 打印全部 82 种设备类型（通道数 / 是否 CANFD / 是否支持经典 VCI） |
| `--selftest` | 跑一遍 连接→发送→接收→关闭，验证驱动与 DLL 是否正常 |
| `--import-test <文件>` | 无界面解析 ASC/CSV/TXT，打印帧数 / ID 数 / 时间跨度 |
| `--curve-test` | 曲线页回归：增删曲线、反复切换显示模式、清空不崩 |
| `--curve-bit-test` | 位信号曲线自检（配了位定义时画的是位信号而非整字节） |
| `--curve-import-test` | 「先导入报文后加曲线」能否自动补齐历史数据 |
| `--asc-repair-test` | 旧版录制日志的负时间戳修复；单点曲线是否可见；恒值 1 的 Y 轴是否为 0~2 |
| `--curve-yaxis-fit-test` | 导入历史后加曲线，Y 轴是否按实际观测范围贴合（不能僵在 [0,1]） |
| `--curve-fitall-test` | Y 轴刻度必须是整数（不能出现 0.5）；点「全览X」后 Y 轴重新贴合；鼠标移出画布后十字光标隐藏 |
| `--curve-diag <asc> [ID] [字节]` | 曲线数据诊断：导入真实文件后 dump 曲线的 X/Y 序列 |
| `--multibyte-cycle-test` | 多字节递增循环：组帧字节序、表格按字节显示、刷新跟帧 |

## 七、常见问题

**Q：双击 exe 提示「找不到 Qt6Core.dll」**
A：没解压，或没跑 `deploy.ps1`。本程序是免安装包，必须**完整解压到本地目录**再运行，不能直接在压缩包里点 exe。

**Q：提示「no Qt platform plugin could be initialized」**
A：缺 `platforms/qwindows.dll`。用 `deploy.ps1` 重新打包即可。

**Q：连不上设备**
A：依次检查 ① 设备驱动是否安装 ② 设备类型/索引是否选对 ③ 波特率是否与总线一致 ④ 部分设备需以管理员权限运行。

**Q：点「发送」没反应 / 接收表格里什么都没有**
A：先确认发送方式选的是哪个：

- `正常发送`：CAN 帧必须被**对端节点 ACK** 才算发出去。总线上只有本机（只插了 CAN 盒、没接对端）时，驱动不会把自己发的帧回灌到接收缓冲，接收表格自然是空的。
- `自收自发`：纯软件回环，**不需要对端节点，也不需要先点「开始接收」**，帧发出去的同时软件会合成一份同内容的 Rx 帧进入接收链路。单机台架上做功能验证就用这个模式。

如果选了 `自收自发` 仍然收不到，跑一下 `MJ_CANScope.exe --loopback-test` 看自检结论。

**Q：网络设备参数填了但连不上**
A：先跑 `MJ_CANScope.exe --nettest` 看参数能否被 ZCAN 内核正确接收；再确认 PC 与设备在同一网段。

**Q：曲线是乱的 / 在 0~255 之间跳**
A：这条曲线画的是**整字节**而不是具体信号。需要在「报文接收配置」里给该字节配上位定义（占字节数选 4bit / 8bit）或多字节跨度。

**Q：数值不对，比如温度显示成几百**
A：检查信号定义里的 `scale` / `offset` 和字节序（大小端），尤其是跨字节的信号。

**Q：Y 轴上出现 0.5 / 1.5 这种小数刻度，值到底是多少？**
A：那是**坐标轴**的刻度，不是信号的值。Y 轴范围按「信号的语义形态」自动贴合：
   0/1 这类开关信号 → `[0, 2]`，刻度落在 `0 / 1 / 2` 三档（整数）；
   恒为 `v` 的信号 → `[v-1, v+1]`，`v` 正好在正中间。
   刻度步长由程序显式指定为整数，所以轴上不会再冒出 `0.5` 这种让人误读的档位。

**Q：点「全览X」之后曲线不见了**
A：旧版本只拉宽了 X 轴，Y 轴还僵在初始范围 `[0,1]`，恒为 1 的信号就贴在轴顶边上 —— 视觉上等于消失。
   现在「全览X」会**同时重新贴合 Y 轴**，曲线始终可见。

**Q：图里那条黄色的虚线是什么？**
A：是**十字光标**（鼠标悬停时显示的读数辅助线）。把鼠标移出画布它会自动消失 —— 之前没有处理鼠标移出事件，所以它会一直留在图里。

**Q：导入 Simulink 模型后信号对不上**
A：用 `--slx-export` 导出 JSON，与 Python 版输出逐字段比对；两边应当完全一致。

**Q：录制的 ASC 文件在 CANoe 里打不开**
A：程序退出时会补写 `End TriggerBlock`，请**正常关闭程序**后再取文件，不要直接杀进程。---

## 八、技术说明

- **曲线控件用 Qwt 而非 Qt Charts**
  Qt Charts 是 GPLv3-only 模块，链接即触发 GPL 传染，闭源商用必须公开全部源码。Qwt 采用 LGPL + 商用友好的附加豁免，适合商业分发。

- **位/字节跨度分开存储**
  `byteSpans` 存**字节数**（1/2/4），`bitSpans` 存**位数**（4/8）。不塞负数进同一字段，是为了让所有读取处都少一次分支判断——任何一处漏判就是越界读内存。

- **报警条件建索引**
  按 `byteIndex` 直接查表（O(1)），而不是遍历条件列表。万帧/秒的总线下，这是每帧 64 次比较的差别。

- **图例按报文 ID 分组**
  不用 QwtLegend（动态网格，做不到同一 ID 同行），改为自绘分组图例。

- **自检模式内置**
  现场排障不必装 Python 或看日志——`--selftest`、`--curve-test` 等直接输出结论到控制台。回归测试也因此能跑在纯命令行环境里。
